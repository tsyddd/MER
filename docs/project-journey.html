我们一路是怎么走过来的：从“辩论”到“自进化”

回顾页，2026-11-05。时间跨度 2026-11-02 至今。数字全部来自 metrics/findings_log.md（F1–F12）。所有样本都是筛选或开发中反复使用的数据，只能看相对差异，不是独立泛化证据。

一、主线：一句话

我们想让多个“专家”辩论来提高视频情感识别的准确率；数据一步步告诉我们：辩论没有帮上忙，而且在最需要它的“专家意见不一致”样本上，辩论的表现约等于随机选一个；真正稳的做法反而是“专家一致就用共同标签，不一致就回到 Direct”。于是我们转向两个问题：（1）能不能把“从专家答案里选对”这件事学出来（自进化：R²-MAD 经验召回、SkillOpt 技能训练）；（2）Gemini 剩下的错误到底是什么。

≈85%样本三位专家有唯一共同标签（一致分支），其中约 81%–83% 答对
≈15%样本不一致（Gemini 62、GPT 55，共 117/400）：v4 辩论只比随机好一点点
6 / 1200Gemini 反思改答案的次数（GPT 13/1200）：反思几乎不起作用
38 / 39 / 35 / 38 / 33Gemini 的 Direct 五次独立运行：单次波动极差 6 条

二、时间线

11-02　v3 → 发现“同模型的专家不独立”（F1、F2）
三位专家 + 汇总器
同一模型的三个角色两两“同时答错”的比例 23%–26%，独立假设下应约 9%；换成跨模型的专家才互补（并集 87%–92% vs 同模型 75%–79%）。这是后面所有“辩论为什么没用”的伏笔。
11-03　v4 → 反思 + 共同标签路由 + 辩论（F3–F5）
80 条、再扩到 400 条，Gemini 与 GPT 各一份
反思几乎不改答案（Gemini 6/1200、GPT 13/1200）；共同标签总是某位专家的主答案，备选标签对“直接输出”没有影响；辩论路径准确率只有 43%–48%，而直接输出路径 83.5%。小数的“错→对”被“对→错”抵消，v4 没有超过多数投票，也没有超过 Direct。
11-03　拆开分支看 → 关键转折（F6、F7）
“一致分支用 v4，不一致分支用 Direct”
不一致分支里，v4 的答对数 ≈ 在候选里随机选的期望（Gemini 26 vs 25.6，GPT 19 vs 22.8），Direct 却是 38 和 26。这个事后组合在 400 条上 Gemini 319、GPT 307，是当时最好的稳妥方案。
11-03　F9 → 专家里其实有正确答案，是聚合把它丢了
“Direct 对、v4 错”的 33 条里，32 条真实标签是某位专家的主答案
也就是说此前“专家信息已经耗尽”的说法是错的，改成“辩论 / 聚合没把对的选出来”。辩论里孤立的正确专家 75%–80% 会改从众，对和错没有区别（F7，11-04）。
11-03～04　v5 → 不一致分支的四种改法（F8、F11、F12）
A 匿名化辩论、B0 / B1 轨迹记分、D 候选取证控制器、E 单 agent 先答再回看
全部没有稳定超过 Direct：A、B0、B1、D 合计 45–51，E 63，Direct 五次均值 60.4（三次投票 61.8）。E 的提升主要来自“首次作答”本身，回看只贡献 2 条；Direct 自己的波动（极差 6 条）比之前估计的大，所以差别 <4 条都不能解读。
11-04　F10 → Gemini 剩余错误的真身
MELD 里把 sadness / fear / disgust / surprise 判成 neutral
一致分支 57 个错误里 49 个是三位专家和 Direct 同错；错误对中 sadness→neutral 10、fear→neutral 8。GPT 能纠正其中 17–23 条，但分不清该纠正哪些。
11-04　文献与方向
自进化辩论：R²-MAD（EMNLP 2026 Findings，training-free）、SkillOpt（NeurIPS 2026，训练一份技能文档）
读了两个仓库的源码，弄清了：R²-MAD 的提示词是静态的，进化的是外部经验库；SkillOpt 进化的是一份全局技能文档，部署时零额外调用。
11-05　设计 → 实现 → 启动 v6 R²-MAD
训练集 ≤400（来自目录去掉旧 400 条的不一致样本），测试 = 旧 400 条里 v4 的 117 条不一致样本
检索键：综合 Caption + 情感识别问题 + 自己上一轮回答（精简）+ 上一轮摘要；bge-m3 余弦；n = 1/2/3 都测；加“不检索”对照 n0。结果（11-06）：n0 / n1 / n2 / n3 合计 44 / 44 / 45 / 47，v4 45，Direct 均值 60.4；未达“有提升”标准（F13，报告）。取回案例的标签只有约五分之一与当前真实标签相同，经验没有给出方向。

3. 辩论为什么没用（F5、F7）

  • 孤立的正确专家 41 个里 32 个改从众；孤立的错误专家 57 个里 42 个改从众：辩论分不清“该坚持”和“该让步”。
  • 辩论后改答案的错→对 / 对→错：Gemini 34 / 34，GPT 23 / 30，近似一场公平的赌局。
  • 提议里有答案（Gemini 55/62）、多数错但标签在提议里的占一半，辩论却只救回 23% / 16%。

四、我们改正过的认识（诚实记录）

  • “MELD 一致分支共同标签错约 60 条” → 实际 Gemini 46、GPT 45。
  • “Direct 的噪声约 ±1–2 条” → 五次独立运行极差 6 条（Gemini 33–39，GPT 20–26）；此前引用的 38 / 26 恰是较高的一次抽样。
  • “不一致分支里专家的信息已经耗尽 / 图谱在误导” → 数据显示答案就在专家里（32/33），是聚合丢掉了它。
  • v5-E 初版有一个没有意义的“≥3/4 视角一致”门控 → 已去掉。
  • “提示词里的‘宁缺毋滥’导致 neutral 过多” → 该句只指证据条数，且提示词另有“证据不足不等于 neutral”；这一解释从未检验，已按原文改写。
  • R²-MAD 的 n 与建库规模：我曾把 n 写成 3，实际原版评测脚本是 1；筛选也从“全池”改为“按配额早停”。

五、我们一直遵守的做法

  • 只比相对差异：样本按模型正确性筛选 / 开发复用，绝对准确率不外推；对照用 Direct 五次均值而不是某一次；“有提升”= 不一致 117 条合并后比均值多至少 4 条，且两个模型各自不低于自己的均值。
  • 先画图、批准后再跑：v5 的每个方法、v6 的两个方法都先出流程图和待确认问题。
  • 标签不进提问：真实标签只用于评估、判对错和写经验库案例的“标准标签”，程序里有 check_no_gold 兜底。
  • 每个结论注明口径和限制，记在 metrics/findings_log.md；进度记在 update.md；结果页都是静态 HTML。

七、悬而未决的问题

  • R²-MAD 的经验能不能把“该坚持 / 该让步”教给专家，还是又变成从众？这是 n1/2/3 相对 n0 要回答的。
  • Gemini 的主要损失（MELD 的 neutral 过度预测）发生在一致分支，不一致分支的任何方法都碰不到它；这部分需要别的办法（例如 SkillOpt 的“技能文档”式规则，或针对 neutral 的校准）。
  • 训练 / 验证集按“至少 3 个模型答对”筛选，偏容易；学到的东西是否适用于真正难的样本没有证据。
  • GPT 的 Direct 一致性不预测对错（五次完全一致的 25 条也只有 48% 答对），“自信地错”需要别的信号。
