两篇多智能体论文的方法框架

TS-Debate（时间序列零样本推理）与 MM-StanceDet（图文立场检测）。帮助理解用的说明页，框架根据论文方法章节整理。

一、先看懂两篇在做什么

共同的问题：让大模型在不训练的情况下，同时利用多种信息（时间序列的数值和图、或者图片和文字）做判断。单个模型容易被某一种模态带偏，例如看图看走眼、数字算错、或文字压过了图。

共同的解法：把任务拆给几个各管一种模态的 agent，让它们各自给出证据，再通过某种机制（辩论、校验、反思）汇总成最终答案。

术语小词典
  • 零样本 / 免训练（zero-shot / training-free）：不改模型参数，只靠提示词和流程。
  • 模态（modality）：信息的形式，如数值、图像、文字。
  • 辩论（debate）：多个 agent 各自给出观点，互相看到对方的内容后修改自己的答案。TS-Debate 强调“协作”，MM-StanceDet 更接近“每人抓住一个立场去论证”。
  • 检索增强（RAG）：先从资料库里找相似的例子，放进提示词里作参考。

二、TS-Debate：Multimodal Collaborative Debate for Zero-Shot Time Series Reasoning

论文定位：把时间序列推理看作“多模态证据仲裁”。视觉形态会误导，数字会被编造，文字上下文也可能盖过信号本身。方法是推理期的多 agent 协议，不需要任何针对任务的微调。

输入：问题 q、时间序列 x（T×d）、可选的文字背景 c。

2.1 角色分工

领域知识

Knowledge elicitor

  • 输入：问题 + 文字背景
  • 输出：领域先验 k
  • 作用：所有 agent 共用的“分析契约”（预期模式、约束、常见错误）
分析者（3 个）

文字 / 视觉 / 数值

  • 文字：解读背景，不直接核对数字
  • 视觉：看时域图和频域图，判断趋势、波动、周期
  • 数值：用 Lookup 工具查数值，做可检验的断言
评审（J=3）

Reviewers

  • 用 lookup 和代码执行核对各模态的断言
  • 给每位分析者的证据打分
  • 输出 VCC 记录（见 2.3）

2.2 流程（按顺序）

第 1 步

知识诱导

  • 从问题和文字背景推出 k：任务特征、领域约束、预期模式、显著属性、推荐步骤、常见失败、哪个模态最重要
↓
第 2 步

构造多模态输入

  • 视图：时间视图（趋势、转折点、极值）、频谱视图（周期）、统计视图（汇总统计、事件）
  • 图：时域多面板图 + 频域多面板图
  • 数值：Lookup(·)，可查区间、邻域、事件、频率信息
  • 文字：原始背景 c
↓
第 3 步（默认 R=2 轮）

协作辩论

  • 第 1 轮：三位分析者各自独立工作，只看自己的模态和 k
  • 第 2 轮起：可以看到其他分析者上一轮的证据，修正、更正或加强自己的立场
  • 允许分歧保留：如果证据确实支持不同意见，就不强行统一
  • 证据格式固定为：理解（Understanding）、观察（Observations，可核对、带标签）、推断（Inferences，带标签）、局限（Limits）
↓
第 4 步

验证-冲突-校准（VCC）

  • 抽取断言：从最后一轮证据中拆出原子断言
  • 验证状态：每条断言标为 已验证 / 未验证 / 被推翻（用 lookup、代码、图是否一致、文字来判断）
  • 领域状态：对照 k 标为 符合 / 违反 / 不适用
  • 证据打分：推断 0–50、观察 0–30、诚实说明局限 0–20
  • 冲突类型：无冲突 / 检出且未解决 / 检出且已解决
↓
第 5 步

校准合成

  • 置信规则：只有关键断言都已验证、符合领域、且无冲突，才给出确定答案；否则保守作答；违反领域约束的断言直接拒绝
  • 时间范围：问过去或现在，直接对照数据；问未来，判断观察到的成因会不会持续，不做简单外推
  • 评审评分：每位评审按 0–20 分的若干标准打分（理解任务、用证据、验证纪律、处理冲突、校准）
  • 兜底：若所有评审都犯方法性错误，合成器重新验证最关键的断言，直接推导答案
关键点：合成器不数票，而是按评审的推理质量和验证结果来决定。这是和普通“多数投票”最大的区别。

三、MM-StanceDet：Retrieval-Augmented Multi-modal Multi-agent Stance Detection

论文定位：图文立场检测。给定图像 I、文本 T 和目标 K，判断对目标的立场。重点是图和文字冲突时怎么办。

输入：(I, T, K)　输出：立场 y ∈ {支持, 中立, 反对}，外加理由。骨干为 gpt-4o-mini。

3.1 流程（四个阶段顺序执行）

阶段 1

检索增强

  • 资料库 D：由训练集构建，每条包含实例、标准立场、以及 MLLM 预先写好的 CoT 解释（说明图文如何与目标对应）
  • 嵌入：CLIP 分别编码图像和文本，合并成一个向量
  • 检索：用近似最近邻找出最相似的 top-k 示例（默认 k=3）
  • 用途：示例（尤其是 CoT）交给后面的“模态冲突”分析者，作为少样本参考
↓
阶段 2

多模态分析（三个专门 agent）

文字分析
  • 只看文字和目标
  • 提取关键词、显式与隐式情绪、讽刺线索、与主题的相关性
图像分析
  • 只看图像和目标
  • 描述相关物体和场景，推断人物情绪，解读颜色、构图、与目标有关的符号
模态冲突分析
  • 同时看图、文、目标和检索示例
  • 判断图文是冲突、互相印证还是各说各话
  • 可以参考示例中的模式
↓
阶段 3（默认 3 轮）

推理增强辩论

  • 三位辩手：各自持支持、反对、中立中的一种立场
  • 输入：原始输入 + 阶段 2 的三份分析
  • 任务：为自己的立场构造最强、最连贯的论证，并引用文字、图像和冲突分析
  • 轮次：第 1 轮各自给出初始论证；之后可以看到其他辩手的论证并加以回应、加强自己的立场
  • 输出：三份互相竞争的论证
↓
阶段 4

自我反思与裁决

  • 裁决者：接收三份论证、原始输入和三份分析
  • 不是挑“最有说服力”的那份，而是逐一检查：前后是否矛盾、是否漏掉了模态冲突、推理是否薄弱
  • 提示词结构：初步判断 → 批判性自省 → 最终决定 → 理由
  • 输出：最终立场 ŷ 和理由

3.2 主要设定与结果

项目设定备注
骨干模型gpt-4o-mini（所有 agent）论文设定
嵌入CLIP图文分别编码后合并
检索示例数 k3超过约 5 后趋于平稳
辩论轮数33–4 轮后收益变小
评价指标Macro F1 
单条成本约 4.8k token，约 27 秒论文给出
检索噪声测试：把 top-3 示例中 0–50% 随机替换成无关条目，性能平滑下降，不会突然崩溃。例如在 MTSE（DT）数据集上，Macro F1 从 70.12 降到 68.92（50% 噪声）。这说明检索的作用是“帮助”，而不是“全靠它”。

如何做最终决定评审打分 + 断言验证标签，合成器按证据质量加权裁决者逐份检查论证后决定
主要保护机制只有验证过的断言才能确定作答；违反领域约束的直接拒绝检索示例提供参考；反思环节检查模态冲突
轮数控制固定 R=2固定 3 轮
两者的共同模式：先把“该看什么”定下来（先验 k 或检索示例），再让分模态的 agent 各自出证据，最后由一个专门的仲裁步骤决定。区别在于 TS-Debate 把仲裁做成了可验证的断言检查，MM-StanceDet 则是论证对论证的裁决。

4.1 如果要借鉴到自己的任务

  • TS-Debate 的 VCC：把“证据质量”变成可检查的标签（已验证 / 冲突 / 违反约束），比直接数票更能说明为什么选这个答案。
  • MM-StanceDet 的冲突分析：专门设一个 agent 只判断“模态是否冲突”，把它的结论交给裁决者，比让每个专家都自己判断更清楚。
  • 检索示例：两篇都说明检索是辅助，噪声下会变差但不会崩溃。
