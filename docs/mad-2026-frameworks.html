五篇 2026 年 ACL / EMNLP 辩论论文的框架图

按各论文方法章节的流程绘制（论文 PDF 取自 ACL Anthology，2026-11-03 阅读），图中的公式、权重、数字来自原文；标注“示意”“读图说明”的是我的解读。只读文献，没有运行任何代码或调用模型。与 论文与源码清单 配套。

一、AgentAuditor：非投票聚合（EMNLP 2026 Main · 2026.emnlp-main.2642）

  • 要解决的问题（§3）：多数投票在 “confabulation consensus” 下失效——相关的 agent 共享偏差、收敛到同一个错误推理，正确推理只出现在少数轨迹里。
  • 推理流程（§4）：① 把每个 agent 的推理切成原子步骤；② 把所有轨迹逐步插入同一棵 Reasoning Tree（语义相近的步骤合并，并记录哪些 agent 经过）；③ 子节点 ≥ 2 的节点是分叉点（CDP），为它造 Divergence Packet（共同前缀 + 各分支的后续证据 + 支持者）；④ Auditor 在每个 CDP 按 rubric 选分支，而不是给整条轨迹打分；⑤ 可选的条件 beam 防止早期误剪。
  • 训练部分（§5，可选）：ACPO 用有标准答案的轨迹构造“共识陷阱”偏好对（正确分支 vs 错误分支，且平衡支持数），用 DPO 训练 Auditor，减少对多数支持的偏好。仓库同时提供 prompt-only 推理，所以不训练也能用。
  • 对我们的意义：输入就是“问题 + K 条 agent 推理”，对应三位专家的输出；但论文评测的是文本 QA 与数学，我们的证据来自多模态感知，切步骤的方式需要自己定。

二、Conformal Social Choice：把候选集做成有覆盖保证的预测集（EMNLP 2026 Main · 2026.emnlp-main.830）

  • 要解决的问题：agent 可能通过社会强化一致地答错，“一致就停”会把这个错误当成最终决定。
  • 四个阶段（§3.2–3.5）：异构 agent 辩论并输出口头概率 → 线性意见池聚合成 P_social → 用校准集上“真实标签的 1 − P_social”分位数得到阈值 q̂ → 预测集 C(x)，再按集合大小决定自动采纳、升级还是全面复核。
  • 保证与边界：固定轮次的边际覆盖保证，不要求单个模型校准；对自适应停止、对逐题正确率都没有保证。论文自己指出，单标签提前出现时的高准确率是选择效应。
  • 对我们的意义：预测集可以代替人工的“专家答案 ∪ 易混淆标签”候选集；难点是需要有标签的校准集，而训练集 320 条是按模型正确性筛选的。

三、Free-MAD：反从众 + 基于整条轨迹的得分（Findings of ACL 2026 · 2026.findings-acl.1600）

  • 要解决的问题（§1）：LLM 天然从众，起初答对的 agent 会被答错的带偏；多数投票只看最后一轮。
  • 辩论阶段（§4.2）：在常规提示后追加反从众 CoT 提示，让 agent 设想存在对抗者、逐条核对分歧。决策阶段（§4.3）：边辩论边给每个候选答案记分——初始答案加分，被放弃的答案扣分，新采纳的答案加分，没变的答案加分；轮次越靠后，影响越小。最终取得分最高的答案，不要求共识。
  • 对我们的意义：得分只依赖“每个 agent 每一轮的答案”，我们已保存的 Round 0 / 反思 / 辩论记录可以直接事后计算。注意论文仓库的情况见推荐页；算法本身只有十几行。

四、Identity Bias：用匿名化去掉“谁说的”这个捷径（ACL 2026 Long · 2026.acl-long.650）

  • 要解决的问题：debate 里的 agent 不中立——会因“这是同伴说的”而盲从（sycophancy），或因“这是我说的”而固执（self-bias）。
  • 做法（§3–§4）：定义 Conformity 与 Obstinacy 两个可直接从日志统计的指标；用 Dirichlet-Compound-Multinomial 信念模型证明两者之差由“信念差”和“身份权重差”组成；把提示里的身份标记全部去掉后，身份权重相等，身份项消失。IBC 就是匿名化前后 Δ 的差。
  • 对我们的意义：我们的专家本来就以模态命名，辩论提示里“图谱专家说…”就是一种身份标记；而指标本身不需要任何新调用。论文的设置是同质 agent、单 peer 环，我们是三位异构专家，指标需要按多 peer 的附录做法调整。

五、Selection Effect：编码器优先的路由，为什么 LLM verifier 帮不上忙（EMNLP 2026 Main · 2026.emnlp-main.1049）

  • 问题：已有一个有监督编码器时，把不确定的样本转发给紧凑 LLM verifier，值不值？
  • 方法（§2）：编码器先预测并给出校准后的置信度，超过阈值的直接接受，其余弃权或转发给 verifier；用 NSGA-II 在 F1、覆盖、成本三个目标上搜索，并把 7 种 verifier（含多 agent 路由与异构投票）和 split-conformal 弃权放在同一个搜索里比较。
  • 结论与边界：转发出去的恰是人类标注者也分歧的难样本，LLM 在这块不比编码器好，放大模型也不改善。论文明确说前提是编码器见过任务自己的标签，否则升级可能值得。
  • 对我们的意义：我们没有监督编码器，“三位专家一致”扮演了闸门的角色，不一致分支就是被转发的难样本切片。这篇论文提示：评估方法时要在同一个切片上和基线比，不能拿全量准确率说话。
