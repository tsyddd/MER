DESIGN · SELF-EVOLVING MULTI-EXPERT INTERACTION

模仿 MCIL 的"最优交互"思路，设计一个训练免费的多专家自进化方法

参考：Zhou, Liang, Gu, Yin, Yao. Multi-Classifier Interactive Learning for Ambiguous Speech Emotion Recognition. IEEE/ACM TASLP, vol. 30, 2022, pp. 695–705, doi 10.1109/TASLP.2022.3145287。以下论文内容取自我对全文的阅读；设计部分是我的建议，尚未实现、未运行、没有成绩。

① 论文的核心不是"测试时讨论"，而是"离线用群体分布重训每个成员"多个不同架构的分类器先在有标签数据上训练，再在无标签数据上投票得到"模糊标签"（投票比例），然后每个分类器用 KL 损失向这个分布重训。测试时各自独立判断，最后选最好的那一个。
② 我们的对应做法把"重训"换成训练免费的状态更新（案例记忆、规则补丁、输出校准）；模糊标签用加权投票分布，候选集用"专家答案 ∪ 第 1 个易混淆标签"（发现 F1）；成员换成跨模型的九位专家（发现 F2）。
③ 和我们做过的辩论有本质区别辩论是在测试样本上互相说服，结果几乎全是从众（辩论 ≈ 投票）。MCIL 式的交互发生在另一批数据上，测试时成员仍然独立，不会把测试判断拉向多数。
④ 需要先说清的限制论文的增益来自梯度重训和大量无标签数据（MAS 的 D2 有 13,400 条）；我们只有 train 的 320 条、不改权重，效果可能小得多。论文最后用测试集准确率选分类器，这一步不能照搬。

一、论文讲了什么

1. 最优交互理论（论文第 III-A 节）

  • 来源：Bahrami 等 2010 年发表在 Science 上的"Optimally interacting minds"。论文引述其结论：能力相近的个体通过交流可以提高表现；同时也引用了该文的另一句话"群体很少胜过其最好的成员"。
  • 心理测量曲线：每个分类器的准确率 P 随数据清晰度 Δc 上升，P(Δc) = H((Δc + b) / σ)，H 是累积高斯函数；σ 越小越敏感。敏感度 S = 1 / √(2πσ²)。
  • 交互后的联合曲线：bjoint = Σ wi bi，σjoint2 = Σ wi2 σi2，权重 wi 与 1/σi2 成正比（逆方差加权）；由此得到 Sjoint ≈ √(Σ Si2) ≥ max Si。
  • 我的理解：这个推导隐含"各成员的误差相互独立"。成员越相关，Sjoint 的提升越小。

2. MCIL 怎么做（论文第 III-C、III-D 节）

  • 精确标签学习：五个不同架构的网络（ResNet、DenseNet、SqueezeNet、VGG、AlexNet）在 D1 上用交叉熵训练。不同架构用来模拟"不同个体的不一致认知"。
  • 构造模糊标签：用训好的网络对无标签的 D2 投票，把投票比例当作每个样本的情绪分布，不需要人工标注。
  • 交互学习：每个网络在 D2 上用 KL 损失向模糊标签重训。
  • 最终决策：在 D3 上选最好的单个网络。论文原文写明这里用的是测试准确率作为衡量能力的标准。

二、哪些能借鉴，哪些不能照搬

论文中的做法我们这里的对应备注
N 个不同架构的分类器跨模型的九位专家：GPT / Gemini / Omni × 图谱 / 音频字幕 / 图像（可加 Direct、PPCT）同模型三角色太相关（见第五节），必须跨模型
D1：有精确标签的训练集train 清单的一半（160 条，有标签）用于估计能力、权重、易混淆先验，以及门控
D2：无标签数据train 清单的另一半（160 条，不看标签）若服务器上还有未被筛选使用的 MER2024 / MELD 样本，可扩充 D2，需另外核实
D3：测试集80 条验证集，最后只评估一次符合项目约定：验证集不参与调参
模糊标签 = 投票比例加权投票分布 Ỹ；候选集 C = 支撑集 ∪ 第 1 个易混淆标签F1：k=1 覆盖率 GPT 75%→82.5%，Gemini 78.8%→83.8%
用 KL 损失重训网络权重训练免费的状态更新：C1 案例记忆、C2 规则补丁、C3 输出校准不改模型权重；C3 最接近 KL 重训
逆方差加权 wi ∝ 1/σi2按 D1 准确率加权，建议 w = log(acc / (1 − acc))这是我建议的分类版对应，不是论文原式
用测试准确率选最好的网络改为在 D1 上交叉验证选不能照搬，否则等于在测试集上调参
Fleiss κ 上升作为效果之一只作监控，停止条件看 D1 准确率辩论实验里"一致但错"很多，κ 上升不代表变好

三、方法设计

流程（伪代码）

members = [(模型, 角色) for 模型 in {GPT, Gemini, Omni} for 角色 in {图谱, 音频字幕, 图像}]

# A. 能力评估（D1，有标签）
for m in members:
    acc[m], confusion[m] = evaluate(m, D1)
keep  = [m for m in members if acc[m] >= max(acc) - δ]         # 论文与理论：能力相近才有交互收益
w[m]  = log(acc[m] / (1 - acc[m]))                              # 建议：分类场景下的"逆方差加权"（独立投票者的最优加权）
prior = 错判次数表(pred → gold, D1)                             # 用于候选集扩展（F1）
state[m] = {cases: [], rules: [], calib: 恒等}                  # 可进化状态，不改模型权重

for t in 1..T:                                                  # B + C：自进化循环（D2，不看标签）
    for x in D2:
        votes  = {m: run(m, x, state[m]) for m in keep}          # 每位成员独立判断，互不可见
        Ỹ[x]   = normalize(Σ_m w[m] · onehot(votes[m]))          # 模糊标签
        C[x]   = support(Ỹ[x]) ∪ top1_confusable(support(Ỹ[x]), prior)
    for m in keep:
        cand = update(state[m], D2, Ỹ, C)                        # C1 / C2 / C3 之一或组合
        if acc_on(D1, m, cand) >= acc_on(D1, m, state[m]):       # 门控：用有标签数据决定接不接受
            state[m] = cand
    if group_acc_on(D1) 不再提升: break                          # 停止条件看准确率，不看一致性 κ

# D. 决策：在 D1 上（交叉验证）选"最好的单个成员"或"候选集 C 内加权投票"，
#    然后在 80 条验证集上只评估一次。
补充说明：循环里"训练什么、怎么验证"的详细解释、图和算例见 docs/self-evolving-training-explained.html。要点：大模型全部冻结，只训练每位专家的校准偏置 b 和融合权重 w；若只做 C3 校准，伪代码里每轮的 run(m, x, …) 不需要重跑大模型，调用量粗估降到 5,000 到 6,000 次。

为什么叫"自进化"

  • D2 上没有人工标签，成员靠"群体分布"互相学习，更新后的成员又产生新的群体分布，循环进行；这对应论文的"交互学习"。
  • 有标签的 D1 只用于两件事：估计成员能力（权重、去掉弱成员）和门控（更新是否被接受、何时停止）。它不进入任何提示词。

三种状态更新的细节与风险

方式做什么主要风险
C1 案例记忆为每位成员建 D2 案例库（样本简述、Ỹ、关键证据）；推理时检索相似案例，附在提示词里作参考相似度怎么算需要选（字幕或组织文本的文本相似、或答案模式相似）；案例的 Ỹ 本身可能是错的
C2 规则补丁统计成员与 Ỹ 的系统性偏离，让模型写 1 条短规则，例如"疑问句加皱眉不自动等于 worried"；只有在 D1 上不变差才保留规则容易过拟合 D1；规则写进提示词需要做版本管理
C3 输出校准让成员在候选集 C 上输出概率分布；用 Ỹ 拟合每位成员的标签偏置（每个标签一个参数），最小化 KLLLM 自报的概率未必可靠；参数虽少，D2 只有 160 条

  • 跨模型成员更互补：κ 更低、并集明显更高（GPT、Gemini 同模型三角色 75% 到 79%，跨模型约 86% 到 92%），"同一个错答案"的比例约减半。

  • 但单靠投票还不够：九位多数投票 61/77，并集 71/77；中间这 10 条正是需要"交互学习"去拿的空间。这只是描述，不是本方法的成绩。

  • train 320 条（MER2024 160 + MELD 160）→ D1 160 条（有标签，两数据集各半）+ D2 160 条（不看标签）。

成本粗估（需要你授权才能跑）

  • train 320 条目前没有感知结果和 v3 专家输出，需要先在服务器上补跑：Gemini 固定图谱约 3 × 320 = 960 次；三个模型的组织文本加三位专家约 4 × 320 × 3 = 3,840 次。
  • 自进化每轮在 D2 上重跑九位成员约 9 × 160 = 1,440 次，T = 2 时约 2,880 次；规则补丁的门控还要在 D1 上额外评估。
  • 最终在 80 条上评估约 9 × 80 + 3 × 80 = 960 次。合计粗估 8,000 到 9,000 次调用。Omni 走服务器上的 vLLM，需要先确认服务状态与 GPU 是否空闲。

六、风险与需要你决定的事

  • 效果可能远小于论文：论文改的是网络权重、D2 上万条；我们只改外部状态、D2 只有 160 条。
  • 项目定位：C1 到 C3 都不改模型权重，仍属于 training-free；但规则补丁会改提示词，需要作为新版本保存，不覆盖 v1 到 v3。
  • κ 不是目标：论文把一致性提升当作成果之一；在我们的辩论实验里，一致后答错的样本很多，所以只把它当监控指标。
  • 开发集复用：80 条已被多次使用，即使只评估一次，也只能算开发集结果。
需要你决定：① 是否授权在服务器上为 train 320 条补跑感知和三个模型的 v3 专家（约 4,800 次调用，含 Omni 的 vLLM 推理）；② 第一步先做哪种状态更新（我建议先做不改提示词、风险最低的 C3 输出校准，加上 B2、B3、M1 对照）。
