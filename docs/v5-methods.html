v5 设计草案：用四种方法替换 v4 的不一致分支

日期 2026-11-03。设计草案，尚未实现、未运行，没有任何 v5 结果。四个方法互相独立，都只替换 v4 的“不一致分支”（三位专家没有共同标签时的辩论），其余沿用 v4 已保存的输出。A、B、C 依据公开源码细化（我读了源码，没有运行），D 是我们自己的设计。示例样本的内容节选自已保存的 v4 输出；唯一算出数字的是 v5-B0（用已保存的记录按规则手算，没有调用模型）。

零、给不熟悉这项工作的读者：任务与流程

图 0　整体流程。同一个大模型扮演三位专家，各自判断并反思一次；三人的答案集合恰好有一个共同标签时直接输出（约 85% 的样本），否则进入不一致分支。v5 只替换不一致分支，四种方法（A–D）互相独立。

任务是多模态情绪识别：给一段几秒的视频（画面、字幕、声音），判断指定人物此刻的情绪，从数据集规定的标签里选一个（MER2024 有 6 个：happy、angry、sad、worried、surprise、neutral；MELD 有 7 个：joy、anger、sadness、fear、disgust、surprise、neutral）。这里不训练任何模型，全部靠调用现成的大模型（GPT 或 Gemini）。

v4 的做法：让同一个大模型扮演三位专家各自判断，再各自反思一次；如果三人的答案里恰好有一个共同标签，就直接输出（约 85% 的样本，答对率约 83%）；否则进入不一致分支（约 15%），v4 在这里让专家辩论。不一致分支是全流程最弱的一块：400 条样本里 Gemini 答对 26/62、GPT 19/55，约等于在候选里随机选（期望 25.6、22.8），而不经过专家的 Direct 答对 38 和 26。v5 只改这一块。

一、v5-A：匿名化辩论

图 1　v5-A 匿名化辩论。①每位专家收到的三份观点（含它自己的）被去掉角色名、随机打乱、不标出哪份是自己的；②三位专家同时看原媒体和匿名观点，各给一个候选内的答案；③三人一致就采纳，否则重新打乱再辩一轮，两轮后仍不一致交给汇总器。其余规则与 v4 相同，因此与 v4 的差别只有“匿名”。

项目内容
论文与源码When Identity Skews Debate: Anonymization for Bias-Reduced Multi-Agent Reasoning（ACL 2026 Long，Choi、Zhu、Li）。官方仓库 deeplearning-wisc/MAD-identity-bias（MIT）。
源码里的做法build_vanilla_prompt：自己的回答写成“This was your most recent opinion”，同伴写成“Agent Opinion 1”。build_anonymized_prompt：把自己的和同伴的回答放进同一个列表、随机打乱，都写成“Agent Opinion 1 / 2”，不再区分自己与同伴。拓扑是单个同伴的环（agent i 只看 agent i+1），所有 agent 同时更新，最后对各 agent 的答案做多数投票（平票随机）。
我们的适配三位专家每人看到全部 3 份（自己 + 两位同伴），去掉角色名和证据前缀后随机编为观点1–3；每位专家、每一轮都重新打乱；汇总器的历史同样匿名。终止与汇总沿用 v4（一致才采纳，最多 2 轮，否则汇总器），这样与 v4 的差别只有“匿名”。
诊断指标（源码 debate/metrics.py）只看“自己上一轮与同伴不同”的情况：从众率 Conformity = P[本轮答案 = 同伴上一轮答案]；坚持率 Obstinacy = P[本轮答案 = 自己上一轮答案]；Δ = 从众率 − 坚持率；身份偏差系数 IBC = Δ(普通) − Δ(匿名)。源码是单个同伴，我们有两个同伴，定义为“本轮答案等于某位与自己不同的同伴的上一轮答案”。先在 v4 已保存的辩论记录上算普通版的 Δ（零成本）。
风险匿名后“多数”仍然看得见；回答的内容会暴露身份（图谱专家引用节点 ID，图像专家多写帧号）。

二、v5-B：Free-MAD（轨迹记分）

图 2　v5-B Free-MAD 轨迹记分。不要求三人一致，而是把每位专家在每一轮的答案按“初始、保持、改口”加减分，取总分最高的标签；平局时用 Direct。B0 直接对 v4 已保存的辩论记录记分（零成本）；B1 先跑一轮反从众批判（同伴匿名，提示“先挑错，多数不算理由”）再记分。右侧数字是示例样本按已保存记录手算的 B0 结果。

项目内容
论文与源码Free-MAD: Consensus-Free Multi-Agent Debate（arXiv 2509.11035；页面标注 Findings of ACL 2026）。仓库 jonathansantilli/freemad（MIT）是第三方按论文算法写的实现，不是论文实验代码。
源码里的做法生成轮：各 agent 独立作答（SOLUTION / REASONING）。批判轮：提示开头是“Anti-conformity critique. Analyze peers for flaws and improvements.”，看到自己的上一轮答案和匿名的同伴答案（Peer #k，默认全连接），输出 DECISION: KEEP 或 REVISE。记分（ScoreTracker）：初始 +w1·f，保持 +w4·f，改答案时旧答案 −w2·f、新答案 +w3·f，f = 1/(k+1)，默认权重 (20, 25, 30, 20)；默认还会把每个答案的分数除以支持过它的 agent 数（normalize=True）。选答案（AnswerSelector）：最高分；平局看校验器置信度，再按字母序。
我们的适配轨迹的轮次：k=0 Round 0、k=1 反思、k≥2 辩论。只记主答案。不做归一化（按论文算法），归一化作为附加对照。平局用 Direct 的答案（在平局内时）。B0 用 v4 已保存的普通辩论记录（零成本，相当于论文 c 变体）；B1 新跑一轮反从众批判（相当于 n 变体），批判时同伴匿名、答案限 C 内。
示例里的计算dia198_utt2 按已保存记录：neutral = 20+20（k=0）+10+10（k=1）+6.7+6.7+10（k=2）= 83.3；anger = 20 + 10 − 8.3 = 21.7。选 neutral，答错。原因是三位专家的记录本身都偏向 neutral，记分规则改不了这一点。
风险在三人都不太对的样本上，记分只是投票的变体；我之前测过的软投票在不一致分支是 29 / 24（Gemini / GPT），低于 Direct 的 38 / 26。

三、v5-C：AgentAuditor（分歧点审计）

图 3　v5-C AgentAuditor 分歧点审计。①把三位专家的证据按“来源 + 位置”对齐，共同观察不再争论，只留下描述不同的分歧点；③每个分歧点打包为“共享上下文 + 分支 A / B”，不写各有几人支持；④审计员看原媒体、回到对应位置判断哪个分支成立；⑤每个胜出分支给它导向的候选一票，平局或没有分歧点时用 Direct。

项目内容
论文与源码Auditing Multi-Agent LLM Reasoning Trees Outperforms Majority Vote and LLM-as-Judge（EMNLP 2026 Main；arXiv 2602.09341）。仓库 weiyang930/AgentAuditor，没有许可证：只借思路，不复制代码。
源码里的做法ReasoningTrie.insert_trace：每一步做句向量，与当前节点子节点的余弦相似度 ≥ 0.82 就合并，否则开新分支，节点记录支持的 agent。PacketExtractor.build_packets：在有两个以上子节点的地方，给每个分支打包共享上下文（前缀最后 5 步）、分支证据（后续最多 3 步，遇到下一个分歧点就停）、支持人数、答案分布（提示里写“仅供参考”）。Auditor._build_prompt：“按过程质量而非人气”，用事实、逻辑、约束、假设、简洁 5 条评判，输出 JSON（胜出分支、置信度、是否致命、理由）。Adjudicator.adjudicate：从根往下，每个分歧点调用一次审计员，最后取胜出子树里的最终答案；胜出无效时选答案最一致的分支。
我们的适配①专家证据直接当作步骤；②证据没有先后顺序，前缀树不适用，改为一次文字调用按“来源 + 位置”对齐，分出共同观察和分歧点（这是与源码最大的不同）；③共享上下文 = 共同观察，默认不给支持人数；④审计员必须看媒体并回到对应位置核对（源码只看文字）；⑤分歧点之间是并列的，不是沿树往下，所以改为每个分歧点给胜出分支导向的候选投 1 票，平局或没有分歧点用 Direct。
风险可能找不到有区分力的分歧点；同一位置的描述不同，也可能只是措辞不同。论文是文本推理任务。

四、v5-D：候选取证控制器（我们的设计）

图 4　v5-D 候选取证控制器（我们的设计）。①把专家证据整理成匿名的证据池；②为候选集里的每个标签分别调用一次，在媒体里找支持、反对和能区分候选的证据；③控制器回到写明的位置逐条核对，按“成立、区分力、模态覆盖、反证”比较各候选的证据充分度；④有明确胜者就输出，否则用 Direct。D-lite 把 ② 和 ③ 合成一次调用作为消融。

项目内容
来源你提出的思路：不一致时由一个控制器基于候选集去找证据（引用证据），最后看哪个候选的证据更充分就采用哪个。没有对应的源码，以下每一步都是我的细化，等你审核。
谁看到什么取证调用：看媒体、C、匿名证据池，只负责一个候选，看不到其他取证调用的结果，也不知道专家各自选了什么。控制器：看媒体、C、各候选的证据清单（顺序随机），看不到专家的身份、答案和理由。
“证据充分”的判断规则（写进控制器提示词）①先逐条核对：回到写明的位置，看观察是否成立；②只算成立的证据，同一事实只算一次；③更看重能把这个候选和其他候选区分开的证据；④覆盖的模态越多越好（画面、声音、字幕）；⑤成立的最强反证会削弱这个候选；⑥两边差距不明显时写“不确定”，交给 Direct。
位置偏差候选大多只有 2 个，控制器可能偏向先出现的那个（ACL 2024《Large Language Models are not Fair Evaluators》）。先用随机顺序；如需要，再加“交换顺序各判一次”作为附加对照（调用数 +1）。
风险取证调用可能为每个候选都“找”出看似合理的证据；控制器的核对仍是语言判断，没有工具。翻转样本要人工抽查证据是否真能在媒体里定位。

六、统一的评价方法（先定好，再跑）

  • 样本：400 条里的不一致分支，Gemini 62 条、GPT 55 条，共 117 条。对照组是 Direct（38、26），同时列出 v4（26、19）、随机期望（25.6、22.8）、候选集上限（58、49）和三位专家各自的答对数。
  • 算“有提升”：合并 117 条比 Direct 多答对至少 4 条，并且两个模型各自都不低于 Direct。
  • 会同时比较 A、B0、B1、C、D（加可选的 D-lite）五到六个结果，只挑最好的会高估，所以“达标”只表示值得在新样本上验证；所有结果都要报告。
  • 每个方法都报告：答对数（按模型、数据集、验证和训练拆开）、与 Direct 的逐条翻转（改对 / 改错）、整体 400 条（一致用 v4、不一致用该方法）、调用数和 token 数、无效样本数，以及翻转样本的人工抽查。A 另报从众率和坚持率；C 另报有分歧点的样本比例；D 另报“不确定”回退的比例和证据核对结果。
  • 提示词运行前冻结，不在这 117 条上调；每个方法跑一次；真实标签只在算分时读取。训练集样本是按模型正确性筛选的，验证集是开发复用数据，重点看相对 Direct 的差值。
  • 建议顺序：先做零成本的 B0 和 A 的诊断（v4 记录上的从众率），再做 D 和 C，最后 A、B1。

七、请你审核的点（括号里是我的默认）

  1. A：每位专家看到全部 3 份观点（含自己的）、不标注、每轮重新打乱；终止规则沿用 v4，而不是源码的多数投票。（是）
  2. B：k=0 Round 0、k=1 反思、k≥2 辩论；只记主答案；不归一化；平局用 Direct。（是）
  3. C：用一次文字调用代替向量前缀树；默认不给支持人数；审计员看媒体；分歧点最多 3 个，逐点投票。（是）
  4. D：证据池去掉专家名、答案和解释；每个候选一次取证调用；控制器按第四节的 6 条规则判断；“不确定”回退到 Direct；D-lite 作为消融。（是）
  5. 四个方法都只在不一致分支上跑，代码放 versions/v5/，不改 v4；每个方法先做 2–3 条冒烟。（是）
