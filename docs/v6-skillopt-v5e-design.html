SkillOpt 针对 v5-E 的设计（v6-SkillOpt-V5E，第三版）

日期 2026-11-05。只有设计，没有实现、没有运行、没有结果。图中橙色 = 大模型调用，蓝灰 = 程序，青绿 = 技能文档与 SkillOpt。第三版相对第二版：① A 改为“用 80 条混淆矩阵的 top1 扩充候选集（程序）+ 优化器写区分线索”，agent 不能自己加标签；② 技能分首答 / 回看 / 反思三个模块，分模块更新；③ epoch 设为 1，取消先验表更新；④ GPT 的优化器用 GPT 6.1 SOL。

零、一句话

v5-E 是一个全模态 agent：先作答，自己写出拿不准的具体问题，再按它指定的时间窗回看，然后反思给最终答案。SkillOpt 要做的是：训练一份 Markdown 技能文档（三个模块），把“怎么区分易混标签、什么时候该写不确定点、回看怎么看、什么时候该改答案”这几类经验写进去，训练完冻结，拼进 v5-E 的三个提示词里。模型权重不动，推理时不增加调用。另外，候选集由程序按混淆矩阵扩充，agent 只能在扩充后的候选集里选。

一、技能文档放在哪里

图 1　v5-E 的流程，以及技能文档拼进哪里。橙色三步是现有的 v5-E（versions/v5/orchestra.py）：首次作答 → 有不确定点才回看 → 反思。底部青绿色是新增的技能文档：一个提示词、三个模块（首答 = A 区分线索 + B 何时写不确定点；回看 = C；反思 = D），每个阶段只带自己的模块，输出字段与格式校验不变；起点只有空标题。候选集由程序扩充成 C′（图 5），三个阶段都只能在 C′ 里选。右侧是 v5-E 现有的表现：只有 13 条写了不确定点，答错的绝大多数没被标记——这是技能最可能起作用的地方。

验证集从哪里来

从训练用的同一个不一致池里切出 25%，不另找数据。考虑过并放弃的两个来源：

  • 新选的 60 条验证：它们按“至少 3 个模型答对”筛，偏容易，三专家不一致的只有 Gemini 2 / 42、GPT 7 / 42，没法当门控。
  • 项目原来的 80 条验证：AGENTS.md 规定验证集不得参与方法调参；而且其中 20 条已经在 117 条测试里。

所以三个集合互不重叠：训练和验证来自旧 400 条之外的池，测试是旧 400 条。新选的 460 条（200 + 30 × 2）这一版不使用。

新发现，需要你判断：MELD 对话泄漏。池里不一致的 MELD 样本中，有一大半和旧 400 条（测试来源）来自同一段对话——Gemini 117 / 204，GPT 228 / 381（旧 400 条的 MELD 样本覆盖了 138 段对话）。同一段对话里说话人、场景、相邻话语的情绪都相关，如果训练 / 验证和测试共享对话，结果会偏乐观。所以本设计在 MELD 上去掉这些样本，代价是 Gemini 的 MELD 训练 + 验证只剩 87 条、GPT 的只剩 153 条。MER2024 没有对话 / 影片编号，做不了同类检查，这是已知限制。
这也影响正在跑的 R²-MAD（v6）：它的训练集是同一个池的前 200 条不一致样本，只按样本编号去掉旧 400 条，没有按对话去重；它又是检索式的（取相似案例的标准标签），受同对话邻居的影响比技能文档更直接。我没有改动正在运行的任何东西，是否处理由你决定。

五、候选集扩充（A）：用 80 条混淆矩阵的 top1

图 5　候选集扩充与 A 的区分线索。程序按混淆矩阵给每条样本的候选集 C 加上扩充标签，得到 C′；提示词里明确哪些是原候选、哪些是扩充；agent 只能在 C′ 里选，不能自己加标签。A 里“凭什么线索区分”由优化器写，与 B、C、D 一样每一步都可以改。

规则

  • 矩阵口径：只用 80 条旧验证样本；按提供方（Gemini、GPT）分开、按数据集分开、区分方向。方向的含义是：当前候选标签是 c，数“答案是 c 时真实标签是 g”的次数。
  • 取法：对候选集 C 里的每个标签 c，取 top1 的 g(c)（先比不同样本数，再比事件数）；该 c 没有记录就不扩充。
  • 来源标记：g(c) 已在 C 里 → 算原候选；不在 → 算扩充。原本就有的，即使扩充里也有，仍算原候选。
  • 作答：agent 只能在 C′ 里选；首答、回看、反思三个阶段用同一个 C′。

每项写作“c → g（支持的不同样本数 / 错判事件数）”。事件数是同一样本在 5 组结果里被重复计数的总和。

要留意的事实：矩阵拆成“提供方 × 数据集 × 方向”之后非常薄。四张表里，只有各一个标签有 ≥ 3 个不同样本支持（Gemini：MER 的 worried、MELD 的 neutral；GPT：MER 的 worried、MELD 的 anger），其余 top1 只有 1–2 个样本，还有标签完全没有记录。也就是说大多数扩充标签依据很弱，可能只是噪声。你已决定不设最小支持数，我会照做，但结果里会逐项报告每个扩充的支持数。

已知限制（你已决定先不处理）：① 这 80 条里有 20 个样本在 117 条测试里（Gemini 15、GPT 8），矩阵含它们的标准标签，结果必须标注，不能声称无泄漏；② 矩阵反映的是 Direct / PPCT / v1–v3 的错误，不是 v5-E 的；③ 旧分析里，专家全错的样本中真实标签落进扩充后候选集的比例约 60%，随机期望约 63%（GPT，旧表、t = 5，不是本页的 top1 方向矩阵），所以扩充不一定提高覆盖；④ 基线没有扩充，增益无法拆成“扩充”和“技能”两部分，这一点你说先不管。

九、风险与对策

#风险依据对策
1回看、反思模块的门控“不降低”会放进无效补丁：这两个模块只影响被标记要回看的样本（v5-E 无技能时约 11%，13 / 117），验证集 47 / 81 条里只有约 5–9 条会触发回看，补丁多半不改变答对数，“不降低”会把它们当通过F12；用户决定改用 ≥ 当前已按你的决定；代价是这两个模块的补丁实际上几乎没有验证，结果里单独报告它们改了什么、有没有改变答案；冻结前人工通读
