六个黑盒、免训练方法的框架图

按各论文方法章节的流程绘制（论文 PDF 取自 ACL Anthology / arXiv，2026-11-03 阅读），图中的公式、阈值和数字来自原文；标注“我们的对应”“读图说明”的是我的解读。只读文献，没有运行任何代码或调用模型。与 黑盒方法清单 配套。

一、MEDitor：分歧才升级，候选约束的裁判可弃权（Findings of EMNLP 2026 · 2026.findings-emnlp.2014）

  • 流程（§3）：两位异构专家各做 10 次只输出标签的采样（T=0.7），多数票得候选 y，前两名的票差当“决断度”τ；二者一致就直接返回。分歧才进深路径：证据协调者（EGC）检索并整理成“按候选对齐”的证据包（它不给答案）；可选地让专家带着证据辩论 3 轮（只改写理由，答案不变）；受限裁判只输出 CHOOSE_A / CHOOSE_B / ABSTAIN；弃权则按 λ·τ + (1−λ)·证据支持度 做确定性回退。
  • 黑盒性：只用各专家的文字回复和采样票数，代码核查未发现 logits / 隐藏层 / logprob 相关调用；检索用 MedCPT，是外部工具。
  • 要记住的限制：任务是文本医学选择题，深路径依赖检索；作者承认对 70B 基线只是“持平”（+0.37，不显著）；深路径在 2,398 个分歧样本里仍留下 754 个“错保持”。仓库 README 与论文摘要用的基准集合不同（4 个 vs 5 个），数字以论文为准。

二、CAST：只在多数 / 少数都有一定占比时才触发对比式仲裁（EMNLP 2026 Industry · 2026.emnlp-industry.229）

  • 流程（§3）：先做 K=5 的自一致性；投票置信度 C 低于 0.70 且第二名占比 m ≥ 0.20 才触发。触发后按答案分簇、每簇挑最有代表性的推理（簇内两两 Jaccard 最高），把多数方与少数方的最强论据并排给模型，要求“找出能裁定分歧的证据并明确裁决”，再采样 8 次，只用这 8 次的多数票（丢掉 Phase 1 的票）。
  • 黑盒性：置信度就是样本一致度，没有 logprob。
  • 要记住的：论文里没有代码链接，但机制描述得清楚，可自行实现；阈值是在 200 题 MedMCQA 留出集上选的；实验是同一模型的多个样本，不是异构专家。

三、Cascade-SC：强教师的独立答案是否落在候选集内（EMNLP 2026 Main · 2026.emnlp-main.1572）

  • 流程（§3）：弱生成器采样 k 条得到候选集 A⁺；强教师独立给一个答案 t。若 t 与某个候选等价（包含门通过）就直接采纳 t；否则教师再采样 k_T−1 次，只对教师样本做多数票（不与候选合并），所以输出可能落在候选集之外。
  • 黑盒性：只需要教师的最终答案，闭源 API 即可。
  • 要记住的：仓库链接是 404（可能尚未公开）。“Direct 当教师”是我对应到我们任务的类比，F6 的数字提示这道门在我们这里几乎起不到筛选作用；这只是观察，没有试过。

四、R²-MAD：经验记忆 + 提示层的置信降权（Findings of EMNLP 2026 · 2026.findings-emnlp.1753）

  • 流程（§4）：每个 agent 有自己的经验库。每一轮用“辩论状态”（自己上一轮回答、上一轮摘要、共识比例）检索：先按余弦取 top-3K，再用 MMR 选 K 条，其中的权衡系数随共识比例变化。检索到的经验一方面修正先验，另一方面用来估计同伴 j 的可靠度，并以“高 / 低置信”的文字标注写进提示。辩论结束后把本次辩论写回经验库。
  • 黑盒性：论文明说因为黑盒 LLM 的 token 概率改不了，所以权重只在提示层实现；代码核查未发现内部输出调用。
  • 需要你先判断的一点：经验库存的是“历史辩论的对错”，来自带标签的训练集。AGENTS.md 规定“真实标签、既有预测及训练 / 验证选择信息不得进入被测模型的推理请求”，这类经验与标注是否算在内，需要你定。我之前在页面里写“训练集 320 条可作经验库”，现在看这句说得太轻了。

五、DebateLedger：把辩论记成转移账本（NeurIPS 2026 Evaluations & Datasets · 仓库 LiXin97/DebateLedger）

  • 流程：按“初始多数 / 最终多数是否正确”把每场辩论记成保持、坍缩、纠正、未修复四类，并记录首次破坏正确多数的轮次；再用“签名回放”评估干预——同一批已保存的辩论上，统计一个规则预防了多少坍缩、又损失了多少纠正。
  • 黑盒性：只用各轮答案与真值；规则解析，不用 LLM 打分；代码核查未发现内部输出调用。
  • 最值得注意的结果：三种“冻结到初始多数”的闸门在等权下都是净负（预防的坍缩少于损失的纠正）。这是对“一致就直接采纳、早停”这类做法的一个反面提醒，值得和我们的路由对照。

六、When Debate Helps：提议命中、可恢复余量与读出（NeurIPS 2026 · 仓库 Wang-ML-Lab/when-debate-helps）

  • 流程：Round 0 的答案集合给出两个指示量——多数票是否对（V）、正确答案是否出现过（P）；“可恢复余量”H 就是 P=1 而 V=0 的比例。辩论后的读出看四个量：恢复 R、新增正确 I、损伤 L，以及 G = H·R + Pr(P=0,V=0)·I − Pr(V=1)·L 这条恒等式。
  • 黑盒性要分开看：指标、“投票再裁判”读出和核实式辩论提示是黑盒；但“专家社会”靠给开源模型权重加扰动构造，受控探针又要比较 log p，这两部分我们用不了。
  • 对我们的意义：先用 H 量出“多数投票漏掉了多少已经出现过的正确答案”，如果很小，改读出方式的空间本来就小。

七、这六个方法可以接在我们流水线的哪里

  • 位置是我读完方法后的建议，没有任何一处被实验验证。其中 5、6 只读已保存日志，零成本；1–4 需要改提示或流水线，要新的模型调用，是否做请你决定。
